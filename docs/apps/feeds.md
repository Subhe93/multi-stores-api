# Feeds app (`feeds`) — Google Merchant / Meta catalog feeds

M5.6 (W2-D). Serves the creator's own published products as a Google Merchant
RSS 2.0 feed and a Meta (Facebook / Instagram) catalog CSV, one feed per
market, from public URLs that carry a secret token. Built because the
client's ads stack needs both feeds and their WooCommerce feed was rejected
for missing GTIN / brand.

## Registry

| key | requires_independent | depends_on | settings exposed to storefront |
|-----|----------------------|------------|--------------------------------|
| `feeds` | false | — | no (the token must stay private) |

Default off; an admin makes it available, the creator switches it on
(`/creator/apps`). Mirrors: `multi-stores-shared/src/constants/store-apps.ts`,
`multi-stores-api/src/common/store-apps/store-apps.registry.ts`,
`multi-stores-dashboard/src/lib/storeApps.registry.ts`,
`multi-stores-web/src/lib/storeApps.ts`.

## Product fields (migration `20261030130000_product_feed_fields`)

All on `Product`, nullable, additive:

| column | type | notes |
|--------|------|-------|
| `gtin` | varchar(14) | GTIN-8/12/13/14, check digit validated on write (`PRODUCT_GTIN_INVALID`) |
| `mpn` | varchar(70) | manufacturer part number |
| `brand` | varchar(70) | falls back to the app's `default_brand` in feeds |
| `google_product_category` | varchar(191) | taxonomy id (`1604`) or full path |
| `condition` | varchar(16) | `refurbished` / `used`; null = `new` |
| `feed_excluded` | boolean default false | never listed in any feed |

DTO (`CreateProductDto` / `UpdateProductDto`): every field optional and
nullable; on update an absent key keeps the stored value (X19 carry-over),
`null` or `''` clears it. `duplicate()` copies all six. The importer is
untouched; a later mapping can fill `brand` through the same DTO.

**G0 (payload stability):** the creator / owner product endpoints
(`GET /products/mine`, `GET /products/:id`, …) carry the six new keys (null
for untouched products). The storefront never carries `gtin`, `mpn`,
`google_product_category`, `condition` or `feed_excluded`; it carries
`brand` only when set (`withoutFeedFields` in `storefront.service.ts`). So a
product without feed data serves a byte-identical storefront payload.

## Settings (`StoreApp.settings`, validated by `feeds-settings.ts`)

```json
{
  "google": true,
  "facebook": true,
  "default_brand": null,
  "token": "<32 lower-case hex chars>",
  "include_variants": true,
  "shipping_label": null
}
```

- `token` is generated by the API (`GET feeds/my/settings` creates one if
  missing; `POST feeds/my/token/rotate` replaces it). `PUT /stores/my/apps/feeds`
  accepts only a generated-looking token (or null) and rejects unknown keys
  (`STORE_APP_SETTINGS_INVALID`).
- `include_variants`: one item per active variant with `item_group_id` =
  product id, else one item per product.
- `shipping_label`: emits `<g:shipping>` (country + service) for every market
  country (the registration country without a market). Empty = none;
  configure shipping in Merchant Center instead.

## Routes

Public (no auth, `@Throttle` 30/min per IP, app must be on):

| route | format |
|-------|--------|
| `GET /api/feeds/:storeSlug/:token/google.xml?market=<key>` | RSS 2.0, `xmlns:g="http://base.google.com/ns/1.0"`, `application/rss+xml` |
| `GET /api/feeds/:storeSlug/:token/facebook.csv?market=<key>` | Meta catalog CSV (`text/csv`) |

- `?market=` picks the market (default market when omitted; ignored when the
  markets app is off).
- One opaque **404 `FEED_NOT_FOUND`** for: unknown slug, inactive store, app
  off, format switched off in the settings, token mismatch (constant-time
  compare), unknown / draft market. The URL space cannot be probed.
- Caching: bodies are built once per store + market + format + variant mode
  and kept **10 minutes** in memory (`X-Feed-Cache: HIT|MISS`,
  `X-Feed-Items`). Response headers: `Cache-Control: public, max-age=600`,
  `ETag` (sha1 of the body), `304` on a matching `If-None-Match`. The body is
  written in 64 KiB chunks. Token rotation drops the store's cache
  (per instance; other instances expire within the TTL).

Creator (JWT, `CREATOR`, `@RequireApp('feeds')`):

| route | returns |
|-------|---------|
| `GET /api/feeds/my/settings` | `{ store_slug, settings, urls[] }` — ensures a token; `urls` has one entry per live market (`market_key` null without the markets app) with `google` / `facebook` URLs |
| `POST /api/feeds/my/token/rotate` | same view with a new token |
| `GET /api/feeds/my/validate?market=` | `{ market_key, currency, products, items, skipped: { excluded, hidden_in_market }, missing_gtin[], missing_brand[], missing_identifier, excluded[] }` — builds the feed in-process |

## Item mapping

| field | source |
|-------|--------|
| `id` | variant id (variants mode) or product id |
| `item_group_id` | product id (variants mode only) |
| `title` / `description` | translation of the market's default locale (fallback: store primary locale → `en` → first); description HTML → plain text, ≤ 5000 chars |
| `link` | `https://<market primary hostname>/products/<slug>`; without a market: the store's `custom_domain` or `STOREFRONT_URL/store/<slug>` |
| `image_link` / `additional_image_link` | variant images first, then product images (featured first, up to 10 additional) |
| `availability` | `in_stock` unless `track_inventory` and stock ≤ 0 (variant stock, else product stock) |
| `price` / `sale_price` | market price through `MarketPricingService.priceProduct` (overrides, FX, rounding); when a compare-at price is higher, `price` = compare-at and `sale_price` = current. Tax: INCLUSIVE stores keep their prices; EXCLUSIVE stores add the product class rate of the market's first country (`resolveRatesForLine`) |
| `brand` | product `brand`, else `default_brand` |
| `gtin` / `mpn` | as stored; neither → `<g:identifier_exists>no</g:identifier_exists>` |
| `condition` | `new` / `refurbished` / `used` |
| `google_product_category` | as stored |
| `product_type` | collection path of the first collection ("Parent > Child") |
| `custom_label_0` | leaf collection name |
| `color` / `size` | variant option values whose option name is a colour / size word (en/de/sv/fr/tr/ar) |
| `shipping` | country + `shipping_label` per market country |

Skipped: drafts (status ≠ PUBLISHED), `feed_excluded`, products switched off
in the market (`ProductMarketPrice.available = false`) and products the
pricing helper cannot price (fixed rule without a rate / override).
Personalised (customizable) products are included at their base price —
the ad platforms show that price; the final price depends on the
customer's options. Provider catalogue products (custom products) are not
listed: feeds cover the creator's own products only.

## Dashboard

- Product form (`ProductForm.tsx`): "Feed data" card — GTIN (client + server
  check digit), MPN, brand, Google product category, condition, "Exclude from
  feeds".
- `/creator/feeds`: `AppTurnedOff` guard; settings form (feeds on/off,
  variants, default brand, shipping label); per-market feed URLs with copy
  buttons; "Rotate token" with confirm; "Validate feed" (per market) showing
  counts, products missing GTIN / brand (linked to the product editor) and
  the excluded list.

## Operations

- No worker, no new env var. URLs use `PUBLIC_API_URL` (`/api/feeds/…`) and
  links use the market hostname / `STOREFRONT_URL`.
- A leaked token: creator rotates it (or disable the app → every URL is 404).
- Feeds are generated on request (30/min per IP, cached 10 min). A very
  large catalogue costs one `findMany` with translations / images /
  variants per rebuild.
